# Athave AI – mobile-first studio update (2026-10-12)

## Delivered

- Same profile verification chip: **Sign in** before authentication and **Verified** afterward. Bottom red action changes **Log in** / **Log out**. Profile is accessible when signed out without an automatic OTP pop-up.
- Login stays securely stored in the existing 14-day server-signed HttpOnly cookie. Per-tab account display data is cached for up to three minutes to avoid repeatedly loading the complete profile, wallets, payments, and generation history. The cache is cleared at sign-out, on server-side 401, and updated after credits change. The backend now returns wallet/history/payments by section rather than fetching everything on every profile visit.
- New `/topup/` route: three compact one-time top-up options, visible together on standard mobile screens. No top-ups on home; home has a single link. All pricing links point to the new route, including JSON-LD offers and sitemap.
- Studio: one upload input accepts **1–6 photos**, each **≤7 MB** (JPG, PNG, WebP). References can be labeled Front, Back, or Detail/Other. These labels travel through both product detection and generation; the backend binds them to signed analysis results. Choose specific views after detection; each generated view still reserves exactly one credit and failures still use the existing wallet refund transaction.
- White background by default, or optional Premium editorial background. Enhanced item-specific image prompts with explicit attention to garment fit/material and electronics/accessory details; prompts discourage invented or removed item features. AI output quality is still model-dependent; manually inspect final results, especially unseen back views and logos.
- Three-dot loading overlays show *real app stages*: optimizing photos, detecting items, generating each selected view, and opening results.
- Product results remain a separate route with authenticated image access and WebP/ZIP downloads.
- Profile redeem input is collapsed into a list action. Contact support email is `imageaiquartz@gmail.com`.
- Search descriptions and structured organization contact updated, PWA service-worker cache version incremented. Native PWA installation remains available, without an injected install button.

## Deploy / testing

- Deploy the **root of this project** to Cloudflare Pages, including `public/` and `functions/api/[[path]].js`. Don't upload just the `public/` directory if your build uses Pages Functions.
- Use your existing secrets, Supabase tables/RPCs, MSG91 keys, and Razorpay account; no extra SQL migration is required for these changes. Existing payment enablement settings still control whether checkout works.
- Ensure deployed `GEMINI_API_KEY`, `ANALYSIS_MODEL` and `GEMINI_IMAGE_MODEL` support the chosen workflows. Generating accurate 1K images, especially text/logos and unseen views, cannot be guaranteed from prompts alone.
- Tests performed: static DOM validation, JavaScript syntax checks, headless mobile view rendering using mocked API responses, uploading multiple test photos, choosing front/back roles, analysis stage transition, logged-in profile badge, collapsed/revealed redeem form.
- Live third-party image generation, OTP, Supabase transactions and Razorpay capture must be smoke-tested on the deployed environment with real keys. **Do not switch on payments before Razorpay is ready**.
